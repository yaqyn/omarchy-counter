# Counter

## Intent
A quiet number in the native Omarchy bar, with a small click-open panel for the Reset, Undo, power, optional goal and counting-key controls. Counting never opens a window, sends a notification, changes focus or repeats while a key is held. The panel inherits the desktop theme; promotional illustrations never override runtime styling.

## Canonical components and tokens
Use qs.Ui.BarWidget, WidgetButton, Panel, KeyboardPanel, Button and ShortcutInhibitor. qs.Commons.Style and Color own typography, spacing, geometry and theme colors; no copied palette. Secondary text uses the theme foreground at full opacity; meaning never depends on reduced contrast. The horizontal bar reserves at least Style.space(44). Counts over 12 digits use an abbreviated visual label with the full count in the accessible name and tooltip. Vertical bars rotate the label and allocate height instead of expanding width. The panel reserves count and feedback geometry, fits/elides long counts and uses plain text throughout. A vertically scrolling viewport keeps controls reachable on short or scaled displays; focus automatically reveals the active control. CounterButton extends qs.Ui.Button with accessible roles/actions and a 32-unit minimum height. Goal reached remains visible in the panel after the brief notification disappears.

## Interaction
Left click, keyboard activation and the Qt accessibility press action toggle the panel. Opening focuses the neutral panel body. Tab traverses Reset, Undo, power, goal entry/save, key chooser and Apply; Enter activates the focused control; Escape and clicking outside close. Reopening discards an unapplied key edit. Reset and Undo are disabled at zero; Reset remains available when saved count is unreadable. Clicking the key starts a focused capture. The next nonmodifier key becomes the selection; Escape cancels without changing it. ShortcutInhibitor is enabled for capture and while the goal field has focus, so a numeric counting key cannot interfere with goal entry. It is released after those flows or panel close. Apply is disabled while capturing, for unchanged selections and while busy. Reset and Undo are disabled during capture. Starting capture clears stale feedback. Errors remain inline. Reset is explicit; Undo subtracts one without going negative.

## State and failure behavior
The count file is authoritative for the total; the versioned state/settings.json file is authoritative for the key. QML reads saved count changes, and refreshes the key on open and after applying. The CLI serializes changes with file locks, atomically replaces complete files, and flushes them to disk. Invalid counts are preserved until explicit Reset. Keys are canonicalized through libxkbcommon, modifiers and conflicting shortcuts are rejected, Hyprland calls have timeouts, and a failed change restores the previous runtime binding and saved settings. Service.qml owns exactly one event-driven helper per compositor. Removal uses token-scoped inline Lua cleanup that survives directory deletion; no permanent configuration changes are installed. Each active service owns exactly two consuming, nonrepeating shortcuts: the unmodified selected key counts; Ctrl + Shift + that key resets. Off releases both, survives reload/restart and guards queued keyboard commands. The panel remains available and the bar adds an off marker. Goal entry uses qs.Ui.TextField with decimal validation, an explicit Save goal action and blank-to-disable. The goal is authoritative in state/goal. Only upward goal crossings notify; notification failure never rolls back a count. The toast requests 1500 ms and is explicitly closed after 1.5 seconds through the notification service. Notification waiting holds no count/settings lock.

## Verification
Isolated Python regression tests cover concurrency, damaged state, atomic-write failure, key validation/conflicts, timeout, malformed desktop responses and rollback. Runtime checks cover clean Hyprland configuration, native panel rendering, keyboard traversal, a successful captured F1/F8/F1 roundtrip, Escape cancellation, modifier handling and capture of the active counting key without incrementing. No browser implementation is involved. Real counter values are not reset during tests.
